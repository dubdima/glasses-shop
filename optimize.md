# Как ускорить и улучшить GoodEye

## Зачем это нужно?
- Чем быстрее примерка — тем больше покупок.
- Большинство заходит с телефонов — сайт должен летать на Android и iOS.
- Поисковые системы любят быстрые сайты.

## Что будем ускорять?

| Что именно | Как упростим |
|------------|---------------|
| 3D-модели оправ | Сожмём в формат glTF/GLB (вместо тяжёлого OBJ) |
| Сама примерка | Используем WebGL + лёгкую нейросеть прямо в браузере |
| Загрузка страницы | Загружаем только нужное, остальное — позже |
| Серверная часть | Добавим кэш (быстрый Redis), не дергаем базу лишний раз |
| Фото, видео | Сжимаем в WebP, отдаём через CDN |
| Счётчики (Pixel, GA4) | Загружаем их без блокировки страницы |
| AmoCRM | Используем вебхуки вместо постоянных запросов |

## Как будем делать?
1. Проверим скорость с помощью Lighthouse и WebPageTest.
2. Сожмём все 3D-модели (будут меньше в 5-7 раз).
3. Настроим ленивую загрузку — фото и модели подгружаются при появлении на экране.
4. Включим Service Worker — сайт будет работать даже при плохом интернете.
5. Используем HTTP/2 и Brotli (современные протоколы сжатия).
6. Сделаем виртуальную прокрутку для галереи с фото клиентов.
7. Результаты распознавания лица будем хранить в кэше 1 час — не пересчитывать заново.
